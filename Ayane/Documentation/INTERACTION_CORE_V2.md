# KIN Interaction Core V2

> 分支：`feature/interaction-core-v2`  
> 目标：在保留 KIN 本地优先、稳定 ID、事件可追溯和跨端安全边界的前提下，重建聊天交互、长期记忆、群聊、生图、关系成长、世界书和角色卡的决策层。

## 1. 设计原则

1. **事实源与派生结果分离**：聊天事件、关系事件和用户确认的信息是事实源；向量索引、记忆排序、好感度总分和提示词拼装均可重建。
2. **模型不能直接改状态**：模型可提出候选记忆、关系事件和群聊发言意愿，最终写入必须经过确定性策略、幂等键和边界检查。
3. **角色、世界书、长期记忆分层**：
   - Character Card：角色身份、说话方式、场景和示例对话。
   - Lorebook：按条件激活的世界设定、人物关系、术语和规则。
   - Memory：从真实互动中提取、可追溯且可更正的用户与关系事实。
4. **弱模型也要安全**：群聊默认使用 Swap Card，仅给当前说话角色完整角色卡；多角色回复顺序生成，后一个角色能看到前一个角色已经完成的消息。
5. **预算先于堆料**：所有召回、世界书和生图上下文都必须有条数与 token 预算，避免永久上下文挤占最近对话。
6. **格式导入不丢字段**：Character Card V2 的未知 namespaced extensions 使用不透明 JSON 值保存，再导出时原样保留。

## 2. 当前落地模块

### 2.1 意图感知长期记忆

`MemoryRetrievalPolicy` 在现有 `MemoryEngine` 之上增加：

- identity / preference / relationship / timeline / task / casual 六类意图；
- 不同意图对应不同召回条数、token 预算、时间半衰期和最低分；
- 对“它呢”“之前那个”这类短指代自动拼接最近用户消息；
- 对身份、偏好和关系问题生成去脚手架查询，减少“你还记得吗”之类词汇干扰；
- 多查询结果使用稳定的 reciprocal-rank 与原始相关度融合；
- 群聊默认排除敏感记忆，防止单聊私密事实被泄露到群中。

后续主链路接入点：用该策略替换 `AppModel` 当前固定参数的记忆召回调用，但保留现有记忆事实表、向量索引和 tombstone 机制。

### 2.2 群聊轮次规划

`GroupTurnPlanner` 支持：

- `manual`：用户手动指定角色；
- `natural`：话题相关度、性格适配、好感度、活跃度与最近发言惩罚综合排序；
- `listOrder`：按成员顺序稳定轮询；
- `pooled`：优先尚未在本轮说话的成员，避免一个角色持续抢答；
- `@角色名`、`@所有人`、外部显式 role ID；
- 禁言与“强制手动发言”分离；
- 自动回复人数硬上限；
- `swapActiveCharacter` 与 `joinCharacterCards` 两种提示词模式；
- 多角色回复强制顺序生成，禁止并发读取过时上下文。

推荐产品默认值：Natural + Swap Card + 自动回复上限 2；手动模式放在群聊输入框旁，而不是藏在群设置深处。

### 2.3 事件账本式好感度

`AffinityProgressionPolicy` 将单一可刷分数拆成：

- warmth：亲近与正向情绪；
- trust：承诺、边界和一致性；
- familiarity：共同经历与长期熟悉度；
- security：互动是否让角色感到安全。

策略包含：

- 每个事件必须有幂等键；
- 同类正向表达使用指数衰减，连续“谢谢你”“我爱你”不能无限刷分；
- 每日正向总增长上限；
- 高分区自然饱和；
- 冲突、拒绝和边界侵犯不受正向上限影响；
- 旧版单一分数可平滑播种四维初始值，总分仍可映射回旧 UI。

禁止将 100 分解释成“绝对顺从”。满分只表示极高亲密、信任和安全感，不取消角色边界、判断力或用户安全限制。

### 2.4 Lorebook 世界书

`LorebookEngine` 和 `LorebookDocument` 支持：

- global / persona / character / conversation 四级作用域；
- 常驻条目与关键词条目；
-主键、次级键及 AND ANY / AND ALL / NOT ANY / NOT ALL；
- 大小写敏感、完整英文词匹配和 `/pattern/ims` 正则；
- 扫描深度与群聊说话人名称；
- 递归扫描、递归层级、延迟至递归、阻止继续递归；
- 概率、稳定随机种子；
- 条目 token 上限、文档 token 上限和全局 token 上限；
- inclusion group 互斥；
- before/after character、before/after examples、depth system/user/assistant 插入位置；
- 确定性排序和可解释激活结果。

世界书不与聊天记忆混存。条目编辑、启停、导入导出和作用域绑定将在独立工作台中完成。

### 2.5 Character Card V1 / V2

`CharacterCardDocument` 支持：

- V1 JSON 导入；
- V2 `chara_card_v2` JSON 导入与导出；
- `{{char}}` / `<bot>`、`{{user}}` / `<user>` 宏替换；
- description、personality、scenario、system prompt、post-history instructions、example messages 与 alternate greetings；
- creator notes 仅作为界面元数据，绝不注入模型；
- 嵌入 character book 映射为 Lorebook；
- 未知 namespaced extensions 无损往返；
- 永久 token、示例 token、缺失字段和过长指令质量报告；
- 兼容 KIN 当前单一 persona prompt 的适配层；
- 可直接调用现有 `createCompanion` 事务创建角色。

### 2.6 生图编排

保留现有已验证的 Images API、OpenRouter Images 和自定义 Chat 网关请求格式，在其上增加：

- 角色名、固定外貌、身份锚点、世界观、当前场景和相关记忆分区拼装；
- 1:1、3:4、9:16、4:3、16:9 构图意图；
- draft / standard / high 质量意图；
- inherit / photographic / cinematic / illustration / anime CG 风格；
- 1–4 张多图，每张使用不同镜头、动作、环境或光线方向；
- 用户负面提示词规范化；
- 仅对 408、409、425、429、5xx 与瞬时网络故障重试；
- 指数退避、请求间隔、取消；
- 部分成功不丢弃，失败按图片索引和尝试次数返回。

下一步设置页需要暴露尺寸、数量、质量、风格和供应商能力探测；不要把所有供应商假设成支持同一组参数。

## 3. 操作逻辑改造建议

### 3.1 单聊输入区

- 发送后立即显示本地消息和“正在组织回复”；
- 流式生成时主按钮变成停止；
- 失败气泡提供重试、复制错误、切换连接；
- 最近一条用户消息支持编辑后重新生成，并明确提示会从该点创建新分支；
- 图片、贴纸和文本附件统一进入一个 `MessageDraft`，退出页面前保留草稿；
- 长按消息操作按“复制 / 引用 / 编辑 / 重新生成 / 删除”稳定排序。

### 3.2 群聊输入区

- 输入框左侧显示当前模式：自然、手动、轮询或抢答；
- 手动模式直接出现成员横向选择，不再进入二级设置；
- 每个成员可在群详情中独立禁言、活跃度和连接配置；
- 回复生成时显示当前角色与队列；
- 用户可停止剩余队列，但保留已经完成的角色回复；
- 群聊私密记忆默认关闭，逐角色显式授权后才允许使用。

### 3.3 记忆可解释性

记忆页每条记录应展示：事实正文、来源消息、置信度、重要度、最近使用时间、为什么被召回。用户可固定、更正、标记私密、删除，并看到冲突候选；不要只展示一个不可解释的“记忆数量”。

## 4. UI 方向

- 保持微信式信息密度，不把 AI 参数堆到聊天主界面；
- 聊天页只暴露高频控制，复杂策略放进角色、群聊、记忆、世界书和服务工作台；
- 所有危险操作使用结果导向文案，例如“删除这条记忆及其索引”，避免只写“确定”；
- 设置页统一使用状态摘要：当前连接、模型、记忆模式、群聊模式、生图能力；
- 世界书和角色卡编辑使用双栏：左侧条目列表，右侧编辑与即时激活测试；
- 角色卡导入先预览再创建，显示 token 预算、警告、首句、创建者备注和内嵌世界书数量。

## 5. 持久化与迁移顺序

1. **兼容层先行**：新策略以纯值类型和服务形式加入，旧数据库无需迁移。
2. **Character Card 导入**：立即映射到现有角色记录；丰富原始卡片随后独立持久化。
3. **好感度账本**：新增事件表与四维快照；旧 scalar score 仅作为迁移初值和兼容展示。
4. **Lorebook 表**：文档、条目和作用域绑定分别持久化，保留 extensions JSON。
5. **群聊配置**：群记录新增策略、prompt mode、每成员 mute/talkativeness；旧群默认 Natural + Swap Card。
6. **生图偏好**：按连接保存能力与用户默认值，消息中只保存生成结果及必要可追溯元数据。
7. **跨端协议**：Swift 和 KMP 共享稳定枚举 raw value、ID、扩展 JSON 与备份版本；平台 UI 可分步实现。

所有迁移必须满足：旧备份可恢复、新版本可重复运行迁移、派生索引可重建、降级时不篡改事实源。

## 6. 验证矩阵

- Memory：意图预算、短指代、敏感记忆群聊隔离、多查询融合稳定性；
- Group：点名、@所有人、禁言、强制手动、轮询、公平抢答、人数上限；
- Affinity：幂等、重复衰减、每日上限、跨日重置、负向事件；
- Lorebook：作用域、主次键、正则、递归、概率、预算、互斥组、插入顺序；
- Character Card：V1、V2、宏、未知扩展无损往返、creator notes 隔离；
- Image：提示词身份稳定、多图差异化、429/5xx 重试、400 不重试、取消和部分失败；
- AppModel：导入事务回滚、群聊时间边界、关系事件与旧分数兼容；
- CI：macOS 测试、iOS Simulator 构建、Android、Windows、privacy gate。
