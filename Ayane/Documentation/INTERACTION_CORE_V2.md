# KIN Interaction Core V2

> 分支：`feature/interaction-core-v2`  
> 本 PR 定位：第二代交互决策层的可合并基础，以及风险可控的首批主流程接线；它不把尚未完成迁移与持久化的领域代码冒充成完整用户功能。

## 1. 设计原则

1. **事实源与派生结果分离**：聊天事件、关系事件和用户确认的信息是事实源；向量索引、记忆排序、好感度快照和提示词拼装均可重建。
2. **模型不能直接改状态**：模型可提出候选记忆、关系事件和群聊发言意愿，最终写入必须经过确定性策略、幂等键和边界检查。
3. **角色、世界书、长期记忆分层**：Character Card 保存角色身份与表达；Lorebook 保存按条件激活的设定；Memory 保存来自真实互动、可追溯且可更正的事实。
4. **弱模型也要安全**：群聊默认使用 Swap Card，仅给当前说话角色完整角色卡；多角色回复顺序生成，后一个角色能看到前一个角色已经完成的消息。
5. **预算先于堆料**：所有召回、世界书和生图上下文均有条数与 token 预算，避免永久上下文挤占最近对话。
6. **导入不丢字段**：Character Card V2 的未知 namespaced extensions 使用不透明 JSON 值保存并无损导出。
7. **迁移先于替换**：涉及 SwiftData、KMP 与备份协议的新事实表，只有完成幂等迁移、恢复和跨端测试后才能替换旧主链路。

## 2. 当前落地模块

### 2.1 意图感知长期记忆

`MemoryRetrievalPolicy` 在现有 `MemoryEngine` 之上增加：

- identity / preference / relationship / timeline / task / casual 六类意图；
- 不同意图对应不同召回条数、token 预算、时间半衰期和最低分；
- 对“它呢”“之前那个”一类短指代拼接最近用户消息；
- 对身份、偏好和关系问题生成去脚手架查询；
- 多查询结果以稳定的 reciprocal-rank 与原始相关度融合；
- 群聊默认排除敏感记忆。

现阶段保留原有记忆事实表、向量索引和 tombstone 语义。AppModel 固定召回参数的全面替换，需要与现有大规模检索、历史原文召回和可解释 UI 一并验证。

### 2.2 群聊轮次规划

`GroupTurnPlanner` 支持：

- `manual`：用户手动指定角色；
- `natural`：话题相关度、性格适配、好感度、活跃度与最近发言惩罚综合排序；
- `listOrder`：按成员顺序稳定轮询；
- `pooled`：优先尚未在本轮说话的成员；
- `@角色名`、`@所有人` 与外部显式 role ID；
- 禁言与强制手动发言分离；
- 自动回复人数硬上限；
- `swapActiveCharacter` 与 `joinCharacterCards` 两种提示词模式；
- 多角色回复强制顺序生成。

现有群消息发送链路已接入 V2 规划器，并保留原有显式 role ID 与数组调用兼容。群聊策略、成员活跃度和禁言的持久化配置仍需后续数据模型与 UI。

### 2.3 事件账本式好感度

`AffinityProgressionPolicy` 将可刷的单一分数拆成：

- warmth：亲近与正向情绪；
- trust：承诺、边界和一致性；
- familiarity：共同经历与长期熟悉度；
- security：互动是否让角色感到安全。

领域策略包含幂等键、同类正向表达指数衰减、每日正向总增长上限、高分区饱和，以及不受正向上限影响的冲突、拒绝和边界侵犯。旧 scalar score 可播种四维初始值，也可映射回旧 UI。

满分表示高亲密、信任和安全感，不取消角色边界、判断力或安全限制。事件表与四维快照持久化尚未替换现有逐消息分数逻辑。

### 2.4 Lorebook 世界书

`LorebookEngine` 与 `LorebookDocument` 支持：

- global / persona / character / conversation 四级作用域；
- 常驻条目与关键词条目；
- 主键、次级键及 AND ANY / AND ALL / NOT ANY / NOT ALL；
- 大小写敏感、完整英文词匹配和 `/pattern/ims` 正则；
- 扫描深度、群聊说话人名称、递归扫描与递归层级；
- 延迟至递归、阻止继续递归、概率与稳定随机种子；
- 条目、文档和全局 token 预算；
- inclusion group 互斥；
- before/after character、before/after examples、depth system/user/assistant 插入位置；
- 确定性排序和可解释激活结果。

世界书不与聊天记忆混存。SwiftData / KMP 持久化、作用域绑定和双栏编辑工作台属于下一阶段。

### 2.5 Character Card V1 / V2

`CharacterCardDocument` 支持：

- V1 JSON 与 V2 `chara_card_v2` JSON 导入；
- V2 JSON 无损导出；
- `{{char}}` / `<bot>`、`{{user}}` / `<user>` 宏替换；
- description、personality、scenario、system prompt、post-history instructions、example messages 与 alternate greetings；
- creator notes 只作为界面元数据，绝不注入模型；
- 嵌入 character book 映射为 Lorebook；
- 未知 namespaced extensions 无损往返；
- 永久 token、示例 token、缺失字段和过长指令质量报告；
- 兼容 KIN 当前单一 persona prompt 的适配层；
- 导入预览后调用现有角色创建事务。

角色卡导入入口已接入角色页面。原始卡片文档持久化、再次导出和与未来世界书工作台的绑定仍待实现。

### 2.6 生图编排

保留现有已验证的 Images API、OpenRouter Images 与自定义 Chat 网关请求格式，并增加：

- 角色名、固定外貌、身份锚点、世界观、当前场景和相关记忆分区拼装；
- 1:1、3:4、9:16、4:3、16:9 构图意图；
- draft / standard / high 质量意图；
- inherit / photographic / cinematic / illustration / anime CG 风格；
- 1–4 张多图差异化；
- 用户负面提示词规范化；
- 仅对 408、409、425、429、5xx 与瞬时网络故障重试；
- 指数退避、请求间隔、取消和部分成功保留。

服务设置仍需暴露数量、比例、质量、风格和供应商能力探测，不能假定所有供应商支持相同参数。

## 3. 操作逻辑方向

### 3.1 单聊

- 发送后立即显示本地消息与组织回复状态；
- 流式生成时发送按钮切换为停止；
- 失败气泡提供重试、复制错误和切换连接；
- 最近用户消息支持编辑后重新生成，并明确新分支边界；
- 图片、贴纸和文件统一进入 `MessageDraft`；
- 长按操作稳定排序为复制、引用、编辑、重新生成、删除。

### 3.2 群聊

- 输入框旁直接显示自然、手动、轮询或抢答模式；
- 手动模式展示成员横向选择；
- 群详情中配置成员禁言、活跃度和连接；
- 回复期间显示当前角色与剩余队列；
- 停止后保留已完成回复，只取消剩余队列；
- 私密记忆默认关闭，逐角色显式授权。

### 3.3 记忆可解释性

记忆页应展示事实正文、来源消息、置信度、重要度、最近使用时间和召回原因。用户可固定、更正、标记私密、删除并查看冲突候选。

## 4. UI 原则

- 保持微信式信息密度，不把低频 AI 参数堆进聊天主界面；
- 高频控制留在聊天页，复杂策略进入角色、群聊、记忆、世界书和服务工作台；
- 危险操作使用结果导向文案；
- 设置页统一显示当前连接、模型、记忆模式、群聊模式和生图能力摘要；
- 世界书和角色卡编辑使用条目列表、编辑区与即时激活测试；
- 角色卡导入先预览再创建，显示 token、警告、首句、创建者备注和内嵌世界书数量。

## 5. 持久化与迁移顺序

1. 纯值策略与兼容层先行，旧数据库无需迁移。
2. Character Card 先映射到现有角色记录，再增加原始卡片持久化。
3. 新增好感度事件表与四维快照，旧 scalar score 仅作为迁移初值和兼容展示。
4. Lorebook 文档、条目和作用域绑定分别持久化，保留 extensions JSON。
5. 群记录新增策略、prompt mode、成员 mute / talkativeness，旧群默认 Natural + Swap Card。
6. 生图偏好按连接保存能力与用户默认值，消息仅保存生成结果及必要追溯元数据。
7. Swift 与 KMP 共享稳定枚举 raw value、ID、扩展 JSON 与备份版本。

所有迁移必须满足：旧备份可恢复、迁移可重复运行、派生索引可重建、降级不篡改事实源。

## 6. 验证矩阵

- Memory：意图预算、短指代、群聊敏感隔离、多查询融合；
- Group：点名、@所有人、禁言、强制手动、轮询、公平抢答、人数上限、旧调用兼容；
- Affinity：幂等、重复衰减、每日上限、跨日重置与负向事件；
- Lorebook：作用域、主次键、正则、递归、概率、预算、互斥组和插入顺序；
- Character Card：V1、V2、宏、未知扩展往返和 creator notes 隔离；
- Image：身份稳定、多图差异化、429/5xx 重试、400 不重试、取消与部分失败；
- AppModel：角色卡导入事务、群聊时间边界、旧接口兼容；
- CI：macOS 测试、iOS Simulator 构建、Android、Windows 与 privacy gate。

## 8. 本 PR 的完成定义

本 PR 只有同时满足以下条件才从 Draft 转为 Ready：

1. 新增领域模块和回归测试可编译；
2. macOS 全量测试与 iOS Simulator 构建通过；
3. Android、Windows 和 privacy gate 通过，外部依赖仓库 403 等基础设施故障必须明确区分并重跑；
4. 群聊与角色卡首批接线不破坏现有行为和备份语义；
5. PR 描述与本表准确区分“已实现”“已接入”和“待迁移”。

完整产品交付仍需后续持久化与工作台 PR；在这些完成前，不把本阶段标记为整个 Interaction Core V2 的最终完成。
